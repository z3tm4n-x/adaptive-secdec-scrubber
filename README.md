# Adaptive SECDED Memory Scrubbing Controller

## Назначение проекта

Репозиторий содержит синтезируемую RTL-модель контроллера адаптивного скраббинга памяти с кодом SECDED 32+7, программный генератор событий ошибок на основе ряда радиационной обстановки и воспроизводимый pipeline численного сравнения стратегий скраббинга.

Проект предназначен для диссертационной проверки метода проектирования SECDED-скраббинга: от критерия применимости при многократных событиях до RTL-реализации контроллера и проверки метрик опасного состояния.

## Основная идея

Контроллер выполняет последовательный скраббинг защищаемой области памяти и изменяет период полного прохода по внешнему уровню радиационной обстановки или управляющей оценке частоты ошибок.

Поддерживаются три стратегии:

1. `fixed` — постоянный период скраббинга.
2. `table` — табличное отображение уровня обстановки в период скраббинга.
3. `threshold` — пороговая стратегия с гистерезисом.

В финальной постановке статьи используется `risk_policy`: расчётная политика, построенная по полному ряду `ν(t)` и затем перенесённая в архитектурно достижимую RTL-шкалу интервалов.

## Protection envelope и dangerous-state audit

Репозиторий поддерживает усиленную диссертационную рамку: скраббинг не рассматривается как средство исправления всех мгновенно опасных многократных событий. Сначала проверяется область применимости SECDED-скраббинга по отчёту `results/paper/protection_envelope/protection_envelope_summary.md`; только после этого период скраббинга выбирается по остаточной допустимой мере для накопительного механизма.

В RTL-стенде дополнительно выполняется post-run verification audit опасных состояний.

Формула аудита: `final_dangerous_words = unique_uncorrectable_words + final_sdc_words`.

`final_sdc_words` и `final_dangerous_words` являются проверочными метриками testbench с внешним эталоном данных. Это не аппаратные выходы SECDED-декодера и не признак того, что сам контроллер способен обнаруживать все SDC-состояния во время работы.

|---|---|
| `rtl/` | Синтезируемые Verilog-модули: SECDED encoder/decoder, модель защищаемой памяти, interval selector, adaptive scrub controller |

| `Makefile` | Основной воспроизводимый pipeline |

## Важная семантика интервала

В актуальной версии RTL `selected_interval` означает целевой период полного прохода скраббинга, а не дополнительную задержку после завершения прохода.

Поскольку последовательный проход памяти занимает ненулевое число тактов, контроллер использует: `effective_wait_interval = max(1, selected_interval - last_pass_duration)`.
