# MBU parameter sources and status

This document defines how the repository treats the MBU parameters used by the applicability criterion.

The criterion uses:

    g_D = sum_m p_m * h_m^(D)
    E_inst = N_events * g_D
    g_D <= E* / N_events

## Parameter meaning

| Symbol | Meaning | Source type |
|---|---|---|
| `p_m` | Distribution of the physical event multiplicity, i.e. the fraction of physical MCU events affecting `m` cells/bits. | Radiation bitmap/statistics, heavy-ion/proton test data, technology-specific literature. |
| `h_m^(D)` | Probability that a physical event of multiplicity `m` becomes logically dangerous for a SECDED codeword under interleaving depth or mapping parameter `D`. In this repository, dangerous means at least two bits of the same physical event land in one SECDED codeword. | Layout/mapping model, interleaving-distance model, bitmap-to-codeword mapping, or deterministic logical baseline. |

The product `p_m * h_m^(D)` separates the physical multiplicity of an event from its logical mapping into protected codewords.

## Value status labels

| Status | Meaning | May be used as a measured technology value? |
|---|---|---|
| `logical_round_robin` | Deterministic logical baseline. Dangerous iff `ceil(m/D) >= 2`. | No. It is a limiting logical model. |
| `illustrative` | Internal demonstration value used to exercise the criterion. | No. |
| `literature_informed` | Scenario value chosen from or bounded by literature, but not directly digitized from a stated figure/table. | Only as a scenario, not as a measurement. |
| `digitized_from_figure` | Value extracted from a named figure/table of a named source. | Yes, with citation and extraction note. |
| `source_required` | Placeholder for future source-backed data. | No. |

## Interpretation rule for dissertation text

Use the logical round-robin table as a deterministic boundary case only.

Use illustrative values only to demonstrate the criterion mechanics.

Use source-backed or explicitly scenario-labeled values when making claims about realistic technologies.

Do not write that `h_m^(D)` is a technology-only constant. It is a property of the pair:

    physical event distribution + memory layout + bit-to-codeword mapping + ECC model

## Suppression requirement

For a single multiplicity class, the applicability condition can be written as:

    p_m * h_m^(D) <= g_crit
    h_m^(D) <= g_crit / p_m

where:

    g_crit = E* / N_events

If the event-rate row is derived from bit-inversion rate `nu(t)` and the mean event multiplicity is `mu`, then:

    N_events = integral(nu(t) dt) / mu

Therefore, using `mu = 1` is the conservative strict case: it maximizes `N_events` and minimizes `g_crit`.
