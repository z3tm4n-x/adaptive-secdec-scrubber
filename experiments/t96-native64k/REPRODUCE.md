# Повтор и независимая проверка

Команды выполняются из корня отдельной ветки релизного контроллера. Использованы Ubuntu 26.04 x86-64 в WSL, Bash, Python 3.14.4 (стандартная библиотека), Icarus Verilog 12.0, Yosys 0.52 (`fee39a3284`) и Vivado 2025.2 (SW Build 6299465) с устройством Zynq-7000. Каталог рабочих результатов лежит вне Git. Для каждого маршрута задаётся новый путь. На данной машине финальный маршрут занял 2 мин 6 с, ограничение Vivado — четыре потока, зарегистрированный максимум памяти процесса — 2960,277 МБ. Последовательная сборка и запуск тестов выполняются из того же набора исходников.

```sh
set -eu
d=experiments/t96-native64k
w=$(mktemp -d)
bash "$d/run_sim.sh" "$w/sim"
bash "$d/run_join.sh" "$w/join"
bash "$d/run_formal.sh" "$w/formal"
bash "$d/run_bounded.sh" "$w/formal"
bash "$d/run_sentinel.sh" "$w/sentinel"
python3 "$d/collect.py" "$w/sim" "$w/join" "$w/formal" "$w/functional.json"
diff "$d/results/functional.json" "$w/functional.json"
export VIVADO=vivado
bash "$d/run_route.sh" "$w/route"
python3 "$d/check_route.py" "$w/route" --output "$w/sta.json"
diff "$d/results/sta.json" "$w/sta.json"
```

В этом запуске переменная VIVADO указывала на пользовательскую обёртку vivado-wsl. Для короткой проверки уже опубликованных первичных протоколов достаточно Python. Команда `unzip -t` или `python3 -m zipfile -t` проверяет целостность архива.

```sh
set -eu
d=experiments/t96-native64k
w=$(mktemp -d)
python3 -m zipfile -e "$d/results/evidence.zip" "$w"
python3 -B "$d/test_edge_budget.py" -v
python3 "$d/collect.py" "$w/sim" "$w/join" "$w/formal" "$w/functional.json"
python3 "$d/check_route.py" "$w/sta" --output "$w/sta.json"
diff "$d/results/functional.json" "$w/functional.json"
diff "$d/results/sta.json" "$w/sta.json"
```

Независимый наблюдатель в `full_tb.sv` получает ожидаемые моменты по номеру внешнего адреса и абсолютному такту. Проверяет физические выходные регистры, состояние всех 16 разрешений направления, данные на активной записи, освобождение и следующий выбор адреса. Данные и ERR намеренно меняются по обе стороны выборки. В проверке истории отдельный алгоритм считает длину календарных интервалов и число до следующего запуска. `join_tb.sv` переносит достижимый префикс проверенного правила в состояние начала граничного прохода. Дальше каждый из 32 768 адресов отрабатывается буквально. На высоких ступенях пропускаются только внутренние такты неактивных базовых интервалов, проверяется каждая граница; один интервал паузы до шага 2 пройден по всем тактам. Внешние входы SRAM задаёт стенд. Реальный физический остаток в скрытых ячейках не наблюдается.

Yosys доказал временной индукцией две группы свойств. Первая связывает изменение истории, разрешающий ноль и выдачу команды с наблюдаемыми входами правила. Вторая связывает каждый из 20 разрядов регистра продвижения с его фазой в календаре и проверяет единственность активного разряда. Третий запуск проверяет совпадение трёх управляющих выводов и адреса при выборе с внутренними сигналами на 142 фронтах от холодного старта при произвольных данных, ERR, потере и запросах приложения. Индукционные свойства относятся к штатной цифровой схеме. Проверка последствий повреждения регистра выполняется отдельными адресными трассами.

Проверка неверного фронта OE# заканчивается строкой `pin plan mismatch tick=7`. Сценарий возвращает код успеха только при обнаружении этой ошибки. Расчёт внешних времён также требует, чтобы подстановка доступа 100 нс дала отрицательный запас непосредственно в строке доступа чтения. Контрольные суммы исходников нормируют окончания строк на LF.

Архив содержит первичные отчёты размещённой схемы, обеих скоростных моделей и обоих направлений внешних сигналов, протоколы функциональных и формальных проверок. Из текстов убраны абсолютный путь рабочей области и имя компьютера. Двоичная контрольная точка Vivado и временные продукты повторно создаются командой выше.

Уточнение о двух краях повторяется по исходному архиву поставки `6b9fb6c`, SHA-256 `06254b262b02faed7f4612e1b176764869bab12597fefc670d7b615ca24e3cee`. Тест отдельно извлекает крайние задержки из 16 отчётов `clocked_*.rpt`, подставляет противоположные отклонения двух фронтов в формулу чтения и проверяет уменьшение каждого из 14 внешних запасов ровно на 1 нс. В `sta/timing.rpt` проверяются сводка всего проекта и строка `clk_i` таблицы Intra Clock. В `sta/effective.xdc` проверяются ограничения рабочего такта. В `functional.json` обновлены контрольные суммы проверяющего кода.
